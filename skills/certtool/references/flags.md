# certtool flags

`certtool --help` prints the same list from the binary itself. Lists such as `--hostnames` and `--chain` are comma-separated.

## Output and certificate

| Flag | Default | Description |
| ---- | ------- | ----------- |
| `--public-certificate` | `app.crt` | Certificate file to write (PEM). With `--yubikey-generate-root`, receives the YubiKey root certificate. |
| `--private-key` | `app.key` | Private key file to write (PEM, mode `0600`). |
| `--ca` | `false` | Make a CA certificate that can sign other TLS certificates. |
| `--max-path-len` | `-1` (no limit) | With `--ca` or `--yubikey-generate-root`: how many CAs may sit below this one. `0` lets it sign only leaf certificates. |
| `--permitted-dns-domains` | | With `--ca` or `--yubikey-generate-root`: DNS domains that certificates below the CA may use (`example.com` includes subdomains; `.example.com` only subdomains). |
| `--permitted-ip-ranges` | | With `--ca` or `--yubikey-generate-root`: IP ranges in CIDR notation that certificates below the CA may use. |
| `--key-type` | RSA-2048, or the `--target` profile's type with `--code-sign` | `RSA-2048`, `RSA-4096`, `ECDSA-256`, `ECDSA-384`, `ECDSA-521`. |
| `--validity` | `8760h` | Lifetime as a Go duration (`h`, `m`, `s`; no `d`). |
| `--hostnames` | | DNS names and IP addresses added as SANs. `localhost` and `127.0.0.1` are always added in TLS mode. Ports are removed; a wildcard must be the leftmost label of a name with two more labels (`*.example.com`). |
| `--parent-public-certificate` | | Issuer certificate. Requires `--parent-private-key`. |
| `--parent-private-key` | | Issuer private key, as unencrypted PEM (PKCS#1, SEC 1, or PKCS#8). Requires `--parent-public-certificate`. |

## Code signing

| Flag | Default | Description |
| ---- | ------- | ----------- |
| `--code-sign` | `false` | Make a code signing certificate instead of a TLS certificate. |
| `--target` | `windows10` | `windows10`/`win10` and `windows11`/`win11`: ECDSA P-256 in an AES-256 `.pfx`. `windows7`/`win7`/`windows8`/`win8`: RSA-2048 in a 3DES `.pfx`. `linux`: PEM certificate and key for `osslsigncode`. `android`: RSA-4096 in an AES-256 `.pfx` keystore for `apksigner` and Gradle. |
| `--pfx-output` | `codesign.pfx` | `.pfx` file for the Windows and Android targets. |
| `--pfx-password` | `$CERTTOOL_PFX_PASSWORD` | `.pfx` password. Prefer the environment variable. Empty means no password. |

## Hierarchies and specs

| Flag | Default | Description |
| ---- | ------- | ----------- |
| `--chain` | | Certificates per layer from the root down, for example `1,1` (root and leaf) or `1,2,3`. A single number such as `3` makes standalone leaves. |
| `--name-prefix` | | Prefix for every common name generated by `--chain`. |
| `--spec` | | YAML spec to generate from. Cannot be combined with `--chain`. |
| `--output-dir` | `.` | Directory for `--chain` and `--spec` output. Created if missing. |
| `--overwrite` | `false` | With `--spec` or `--chain`, regenerate every certificate instead of reusing the `.crt` and `.key` files already in `--output-dir`. |
| `--export-spec` | | Write the spec built from `--scenario`, `--chain`, `--spec`, or plain flags to this YAML file and generate nothing. `-` writes to standard output. |
| `--scenario` | | Write a commented spec to `--output-dir`, as `<scenario>.yaml`, and generate its certificates; with `--export-spec`, only write the spec. Comma separated: `web`, `local-dev`, `mtls`, `microservices`, `database`, `active-directory`, `kubernetes`, `vpn`, `eap-tls`, `iot`, `kafka`, `docker`, `git`, `ssh`, `ftps`, `ios`, `android`, `android-signing`, `code-sign`, `proxy`. Running it again reuses the spec and certificates, and stops if the spec was edited. Each scenario's inputs are `--hostnames`, `--clients`, or `--target`; `docs/scenarios.md` says which. Uses the subject flags, `--key-type`, and `--validity` for the leaves; other flags are errors. With `--yubikey` the root is left out. `.pfx` passwords come from `CERTTOOL_PFX_PASSWORD`. |
| `--clients` | | Common names of the client certificates, users, or devices a scenario makes, comma separated. |

## YubiKey

| Flag | Default | Description |
| ---- | ------- | ----------- |
| `--yubikey` | `false` | Sign with the root CA on a YubiKey. Works with single certificates, `--chain`, and `--spec`. Cannot be combined with the parent flags. |
| `--yubikey-generate-root` | `false` | Generate a root CA key on the YubiKey and store its self-signed certificate there. Key types: `ECDSA-256`, `ECDSA-384`, `RSA-2048`, `RSA-4096` (firmware 5.7+). |
| `--yubikey-serial` | | Which YubiKey to use when more than one is connected. |
| `--yubikey-slot` | `9c` | PIV slot: `9a`, `9c`, `9d`, `9e`, or `82` through `95`. |
| `--yubikey-pin` | `$CERTTOOL_YUBIKEY_PIN` | Required by both YubiKey modes. Prefer the environment variable. |
| `--yubikey-management-key` | `$CERTTOOL_YUBIKEY_MANAGEMENT_KEY` | Hex management key for `--yubikey-generate-root`. Without one, the PIN-protected or factory default key is used. |
| `--yubikey-touch-policy` | `always` | Touch rule for a generated key: `always` (every signature), `cached` (one touch per 15 seconds), or `never`. |
| `--yubikey-overwrite` | `false` | Let `--yubikey-generate-root` replace a slot that holds a certificate. Destroys the old key. |

## Encrypted keys

| Flag | Default | Description |
| ---- | ------- | ----------- |
| `--encrypt-to` | | Comma-separated age recipients (`age1...`, `age1pq1...`, `age1tag1...`, `age1yubikey1...`). Every private key and `.pfx` is written encrypted with an `.age` suffix. Needs no YubiKey. |
| `--age-identity-file` | | Comma-separated age identity files that decrypt an encrypted `--parent-private-key` or the keys `--spec` and `--chain` reuse. `CERTTOOL_AGE_IDENTITY` can hold identities too. |
| `--age-yubikey` | `false` | Decrypt those keys with the YubiKey (slots 82 to 95, 9d). Needs `CERTTOOL_YUBIKEY_PIN`, maybe a touch. |

## Other

| Flag | Description |
| ---- | ----------- |
| `--version` | Print the version and exit. |
