# certtool flags

`certtool --help` prints the same list from the binary itself. Lists such as `--hostnames` and `--ports` are comma-separated.

## Output and certificate

| Flag | Default | Description |
| ---- | ------- | ----------- |
| `--public-certificate` | `app.cert` | Certificate file to write (PEM). With `--yubikey-generate-root`, receives the YubiKey root certificate. |
| `--private-key` | `app.key` | Private key file to write (PEM, mode `0600`). |
| `--ca` | `false` | Make a CA certificate that can sign other TLS certificates. |
| `--key-type` | RSA-2048, or the `--target` profile's type with `--code-sign` | `RSA-2048`, `RSA-4096`, `ECDSA-224`, `ECDSA-256`, `ECDSA-384`, `ECDSA-521`. |
| `--validity` | `8760h` | Lifetime as a Go duration (`h`, `m`, `s`; no `d`). |
| `--hostnames` | | DNS names and IP addresses added as SANs. `localhost` and `127.0.0.1` are always added in TLS mode. |
| `--ports` | | Ports appended to each hostname as `host:port` SANs. |
| `--parent-public-certificate` | | Issuer certificate. Requires `--parent-private-key`. |
| `--parent-private-key` | | Issuer private key. Requires `--parent-public-certificate`. |

## Subject

| Flag | Default |
| ---- | ------- |
| `--common-name` | the `--organization` value |
| `--organization` | `cloudfra` |

| `--locality` | `Seattle` |

## Code signing

| Flag | Default | Description |
| ---- | ------- | ----------- |
| `--code-sign` | `false` | Make a code signing certificate instead of a TLS certificate. |
| `--target` | `windows10` | `windows10`/`win10` and `windows11`/`win11`: ECDSA P-256 in an AES-256 `.pfx`. `windows7`/`win7`/`windows8`/`win8`: RSA-2048 in a 3DES `.pfx`. `linux`: PEM certificate and key for `osslsigncode`. |
| `--pfx-output` | `codesign.pfx` | `.pfx` file for Windows targets. |
| `--pfx-password` | empty (no password) | `.pfx` password. |

## Hierarchies and specs

| Flag | Default | Description |
| ---- | ------- | ----------- |
| `--chain` | | Certificates per layer from the root down, for example `1,1` (root and leaf) or `1,2,3`. A single number such as `3` makes standalone leaves. |
| `--name-prefix` | | Prefix for every common name generated by `--chain`. |
| `--spec` | | YAML spec to generate from. Cannot be combined with `--chain`. |
| `--output-dir` | `.` | Directory for `--chain` and `--spec` output. Created if missing. |
| `--export-spec` | | Write the spec built from `--chain`, `--spec`, or plain flags to this YAML file and generate nothing. |

## YubiKey

| Flag | Default | Description |
| ---- | ------- | ----------- |
| `--yubikey` | `false` | Sign with the root CA on a YubiKey. Works with single certificates, `--chain`, and `--spec`. Cannot be combined with the parent flags. |
| `--yubikey-generate-root` | `false` | Generate a root CA key on the YubiKey and store its self-signed certificate there. Key types: `ECDSA-256`, `ECDSA-384`, `RSA-2048`, `RSA-4096` (firmware 5.7+). |
| `--yubikey-serial` | | Which YubiKey to use when more than one is connected. |
| `--yubikey-slot` | `9c` | PIV slot: `9a`, `9c`, `9d`, `9e`, or `82` through `95`. |
| `--yubikey-pin` | `$CERTTOOL_YUBIKEY_PIN` | Required by both YubiKey modes. Prefer the environment variable. |
| `--yubikey-management-key` | `$CERTTOOL_YUBIKEY_MANAGEMENT_KEY` | Hex management key for `--yubikey-generate-root`. Without one, the PIN-protected or factory default key is used. |
| `--yubikey-touch-policy` | `cached` | Touch rule for a generated key: `never`, `always`, or `cached` (one touch per 15 seconds). |
| `--yubikey-overwrite` | `false` | Let `--yubikey-generate-root` replace a slot that holds a certificate. Destroys the old key. |

## Other

| Flag | Description |
| ---- | ----------- |
| `--version` | Print the version and exit. |
